# Stackchan Strider ファームウェア

M5Stack 製品版スタックチャン(K151 / CoreS3)を、首振り(ヨー)サーボの連続回転で歩かせるファームウェア。
画面はスタックチャンの顔で、スマホのブラウザから前進・後退・停止を操作する。

**状態: 製品版スタックチャン 1 台に書き込み、家の Wi-Fi の設定から操作ページでの歩行まで動くことを確認した(2026-11-18)。つなぎ方を選ぶ画面と「直接つなぐ」は 2026-11-19 に足した部分で、同じ日に実機 1 台に書き込んで動いた。**

## 書き込む前に

- 書き込むと、出荷時のアプリ(AI エージェントなど)は起動しなくなる。元に戻すには、下の「元に戻す」の手順でバックアップを書き戻すか、M5Burner で公式ファームウェアを書き直す。
- CoreS3 の電源を入れてからパソコンにつなぐ。「USB シリアル デバイス (COMx)」として見える(ESP32-S3 の USB-JTAG/シリアル)。

## 書き込み

**アプリ本体だけを `0x20000`(出荷時の 1 番目のアプリ領域 ota_0)に書く。** ブートローダー・領域配置・設定領域(NVS)は出荷時のまま残す。NVS にはサーボの原点調整値(名前空間 `servo`)が入っているので、消さない。

PowerShell で実行する(Git Bash では ESP32 のツール導入が失敗する)。COM8 は実際のポート番号に置き換える。

```
cd firmware
pio run
$py = "$env:USERPROFILE\.platformio\penv\Scripts\python.exe"
& $py -m esptool --chip esp32s3 --port COM8 --baud 921600 write-flash 0x20000 .pio\build\stackchan\firmware.bin
```

ビルド済みのアプリ(`stackchan-strider-app.bin`、書き込み先 `0x20000`)は、GitHub の Releases に置く。

注意:
- `pio run -t upload` と、ビルドで出来る `firmware.factory.bin` は使わない。PlatformIO は起動スロット情報を `0xe000` に書くが、この機体の領域配置では `0xd000` にあり、ずれる。
- 出荷時の起動スロットが ota_0 であることが前提(2026-11-17 の個体では、otadata の世代番号が 3 と 2 で ota_0 が選ばれていた)。公式ファームウェアをオンライン更新した直後などで ota_1 から起動している個体では、`0x20000` に書いても出荷時アプリが起動する。その場合は otadata を初期化する(`boot_app0.bin` を `0xd000` に書く)。
- 領域配置は `partitions_stackchan.csv`(出荷時と同じ)。暗号化とセキュアブートは無効であることを確認済み。

## 元に戻す

**書き込む前に、自分の機体の出荷時の内容(16MB)を丸ごと読み出して保存しておく。** 数分かかる。

```
& $py -m esptool --chip esp32s3 --port COM8 --baud 921600 read-flash 0x0 0x1000000 backup\stackchan_factory_flash_16MB.bin
```

元に戻すときは、保存したファイルを先頭から書き戻す。

```
& $py -m esptool --chip esp32s3 --port COM8 --baud 921600 write-flash 0x0 backup\stackchan_factory_flash_16MB.bin
```

バックアップには、その機体の設定(保存済みの Wi-Fi など)が入りうるので、人に渡したり公開したりしない。

## 使い方

**はじめて起動したとき**、画面に「スマホとのつなぎ方を選ぶ」が出る。どちらかをタッチする。

| つなぎ方 | 向いている場合 |
|---|---|
| 直接つなぐ | 設定なしですぐ使いたい。外出先で使う。スマホのテザリングしか無い |
| 家の Wi-Fi を使う | スマホを家の Wi-Fi につないだまま操作したい |

選んだつなぎ方は本体が覚えていて、次からはこの画面を出さない。選び直す方法は下の表にある。

### 直接つなぐ

本体が Wi-Fi(`Strider-XXXX`、パスワードなし)を出す。スマホをその Wi-Fi につないだまま操作する。

1. 画面に QR が出る(「スマホから操作する準備 1 / 2」)。スマホのカメラで読んで、出てきた Wi-Fi につなぐ。
2. スマホに操作ページがポップアップで開く。開かないときは、スタックチャンの画面が「2 / 2」に切り替わっているので、その QR を読む。
3. 次に電源を入れたときも、同じ手順(QR を読んでつなぐ)で操作できる。

操作している間、スマホの Wi-Fi は本体につながるので、家の Wi-Fi は使えない。

### 家の Wi-Fi を使う

1. 画面に QR が出る(「家の Wi-Fi 1 / 2」)。スマホのカメラで読んで設定用 Wi-Fi(`Strider-XXXX`)につなぐ。
2. スマホに設定ページがポップアップで開く(「キャプティブ…」という名前の画面)。開かないときは、スタックチャンの画面が「2 / 2」に切り替わっているので、その QR を読む。
3. 家の Wi-Fi を選び、パスワードを入れて「この Wi-Fi につなぐ」を押す。同じ名前で 2.4GHz と 5GHz を出しているルーターなら、そのまま選べばよい(本体は 2.4GHz 側につながる)。
4. 本体が再起動して家の Wi-Fi につながると、画面に**操作ページの QR** が出る。スマホは自動で家の Wi-Fi に戻るので、そのまま読む。ページが開くと画面は顔に戻る。`http://strider.local/` でも開ける場合がある。

設定の途中でやめるときは、画面の右上の「つなぎ方を選び直す」をタッチする。

操作ページ:

| 操作 | 動き |
|---|---|
| スティックのつまみを上下に動かす | 前進・後退。中心から離すほど速い(10% から、設定の上限まで)。指を離すと止まる |
| つまみを左右の帯に入れる | その場で向きを変える(右の帯で上から見て時計回り、左の帯で反時計回り)。上下の位置には関係なく、回りながら進むことはできない。回る強さは変えられない。**先に「旋回の調整」が要る** |
| 顔の上下「下へ」「上へ」 | 10° ずつ(0〜60°) |
| 設定 → 旋回の調整をする | 左右に回れるようにするための調整。平らな床に置いて押すと、8 秒ほど歩いて、同じだけ戻る(前に 60 cm ほど空ける)。結果は本体に保存され、電源を切っても残る。歩行ベースを組んだあとに 1 回やる。歩行ベースを替えたとき・組み直したときは、やり直す |
| 設定 → 旋回の調整を消す | 2 回押すと、未調整に戻る |
| 設定 → 歩く速さの上限 | つまみを端まで動かしたときの速さ。20〜100%、初期値は 80%。旋回の強さは変わらない |
| 設定 → 前進と後退を入れ替える | つまみを上に動かして後ろへ歩くときにチェック |
| 設定 → 歩いている間は笑顔にする | 初期状態は OFF |
| 設定 → スマホとのつなぎ方を選び直す | 2 回押すと、つなぎ方の設定を消して、つなぎ方を選ぶ画面に戻る |

本体:

| 操作 | 動き |
|---|---|
| 頭の上をさわって離す | 操作ページの QR をもう一度出す(15 秒たつか、ページが開かれると顔に戻る。残り秒数を画面に出す)。直接つなぐ設定でスマホがつながっていないときは、Wi-Fi の QR を出す |
| 頭の上を 5 秒さわり続ける | 画面に「スマホとのつなぎ方の設定を消しますか?」と出る。画面の「消す」をタッチしたときだけ消して再起動し、つなぎ方を選ぶ画面に戻る。「やめる」か 10 秒放置で顔に戻る |

スティックに触れている間はスマホから 0.3 秒ごとに合図を送る。0.9 秒途切れると本体が自動で止まる(離した合図が届かなかった、電波が切れた、など)。画面を切り替えたときも止める。

旋回は、首を全開で 90° の幅で往復させて向きを変える。どちらに回るかは、往復の中心が脚のどの位相にあるかで決まる。首の位置と脚の位相の対応は、歩行ベースの組み方(傘歯車のかみ合う歯、クランクを六角シャフトに差す向き)で変わるので、機体ごとに「旋回の調整」で求める。調整では、歩いている間の機体の揺れを本体のジャイロで測り、揺れの山が首のどの位置に来るかから、往復の中心を決める。

- 調整がまだのときは、つまみを左右の帯に入れても旋回しない。操作ページの状態の行に「旋回は未調整」と出る。
- スタックチャンを歩行ベースから下ろして載せ直しても、調整はそのまま使える(電源を切って載せ直した場合も同じ)。
- 2 つの歩行ベースで確かめた(2026-11-21。同じスタックチャンを載せ替えた)。求めた中心は 660 前後と 328 前後で、どちらも調整のあと左右に回った。別のスタックチャン本体では確かめていない。
- 旋回を始めたときに首が往復の範囲の外にあると、範囲に入るまでの間、少し歩いてから回り始める(首と脚が歯車でつながっているので、無くせない。近い側から範囲に入るようにしてある)。

## 操作ページを作り替える人へ

操作ページ(`src/pages.h`)は、本体と HTTP でやり取りするだけなので、ページを作り替えたり、別のアプリやスクリプトから操作したりできる。どれも GET で、返事は状態の JSON。

| 呼び出し | 動き |
|---|---|
| `/api/stick?x=<-100〜100>&y=<-100〜100>` | スティックの倒れ(右と上が正)。左右が 40 以上なら旋回、そうでなく上下が 15 以上なら歩く(倒れが大きいほど速い)、どちらでもなければ止まる。動かし続ける間は 0.9 秒以内の間隔で送り続ける(途切れると本体が止める) |
| `/api/stop` | 止める |
| `/api/look?pitch=<0〜60>` | 顔の上下 [°] |
| `/api/limit?v=<20〜100>` | 歩く速さの上限 [%](本体に保存) |
| `/api/calibrate` | 旋回の調整を始める(床に置いた状態で呼ぶ。歩いて戻るまで約 16 秒。`/api/stop` で途中でやめられる) |
| `/api/uncalibrate` | 旋回の調整を消して、未調整に戻す |
| `/api/invert?on=<0か1>`、`/api/smile?on=<0か1>` | 前進と後退の入れ替え、歩いている間の笑顔(本体に保存) |
| `/api/state` | 状態だけを返す |

状態の JSON: `drive`(0 停止 / 1 前進 / -1 後退 / 2 右に旋回 / -2 左に旋回)、`invert`、`smile`、`limit`、`volt`(電池の電圧)、`calib`(旋回の調整。0 まだ / 1 調整中 / 2 済み / 3 失敗)、`center`(時計回りに回る往復の中心。-1 = まだ)、`pos`(首のサーボの生の位置)。

歩行と旋回のコードは `src/main.cpp` の `driveTask` と `setStick` にある(画面や Wi-Fi と同じファイル)。旋回のために、サーボとの通信をこのタスク 1 つにまとめているので、公式ライブラリの `M5StackChan.Motion`(首を振る、うなずく)とは同時に使えない。

## 初回の確認(脚を浮かせるか、歩行ベースに載せる前に)

1. 起動して画面に「スマホとのつなぎ方を選ぶ」が出るか。文字が読めるか。ボタンをタッチすると次の画面に進むか。
2. 「直接つなぐ」: QR でスマホが本体の Wi-Fi につながるか。操作ページが開くか(開かなければ、切り替わった画面の QR を読む)。
3. 「家の Wi-Fi を使う」: QR でスマホが設定用 Wi-Fi につながり、設定ページが開くか。家の Wi-Fi を選んで保存すると、再起動して操作ページの QR が出るか。
4. **起動した直後に首が勝手に回らないか。** 公式ライブラリの初期化が首を原点へ動かす場合、歩行ベースに載せていると起動のたびに少し歩く。回る場合は教えてほしい(初期化のあとの扱いを変える)。
5. スティックのつまみを上に動かしている間、首が回り続けるか。離すと止まるか。止まったあと首が勝手に戻ろうとしないか。
6. 歩行ベースに載せ、つまみを上に動かすと前に歩くか。後ろへ歩くなら「前進と後退を入れ替える」にチェックする。
7. つまみを半分ほど上に動かして、クランクが 1 秒に半回転〜1 回転くらいか(シミュレーションの目安は 40 rpm 前後)。
8. 歩行中にスマホの Wi-Fi を切ると、1.5 秒ほどで止まるか。
9. 顔の上下のボタンで頭がうなずくか。イヤーパッドに当たらないか。
10. 床に置いて、設定の「旋回の調整をする」を押す。8 秒ほど歩いて、同じだけ戻るか。終わると「旋回は未調整」の表示が消えるか。
11. つまみを右の帯に入れると上から見て時計回り、左の帯に入れると反時計回りに、その場で向きが変わるか。

## 設計上の決めごと

- 画面の向きは指定しない。この機体(M5Unified のボード番号 27)は初期状態で向き 0・横 320 × 縦 240 で、`setRotation(1)` を入れると 90° 回る。
- **首(ヨー)は連続回転だけで動かす。** 公式ライブラリの `Motion.stop()`・`goHome()`・`moveX()` は首を角度指定に戻す実装で、土台が回り続けるこの機体では原点の角度まで首を回そうとして脚が動く。止めるときは出力 0 の連続回転にしている。
- 歩く速さの上限は、初期値が 80% で、設定で 20〜100% に変えられる。80% は実機で全開まで試して決めた。MuJoCo のシミュレーションでは、全開だと跳ねて 1 回転あたりの前進が減った。旋回は全開で往復させる(実機で、出力を下げると回る角度が減り、40% ではほとんど回らなかった)。
- サーボとの通信は、起動時の準備(電源、首を連続回転モードにする)だけ公式ライブラリに任せ、そのあとは自前のタスク 1 つだけが行う。旋回は首の生の位置を読みながら往復させるので、公式ライブラリの 20 ms ごとのタスクと通信線を取り合わないよう、公式ライブラリの自動の脱力を切り、`Motion` の命令は呼ばない。うなずきも、自前のタスクからサーボに直接指令する。
- 首のサーボは、1 周の約 1 割で位置が読めない(そこでは実際と違う値が返る)。往復がその区間にかかっても折り返せるよう、首の位置を見積もって折り返す。読めた位置が直前の見積もりとつじつまが合えばその値を使い、合わなければ、出力から決めた速さで進めた値を使う。区間を抜けた直後の値で合わせ直す。
- 旋回の調整の基準(揺れの山がこの位置なら、往復の中心はここ)は、往復の中心を実機で 1 つずつ試して探してあった 1 台から決めた。調整は出力 60% で歩かせる(80% では、求まる中心が約 13° ずれた)。
- 顔の描画を止めるときは `avatar.stop()` を使い、描画ループが終わるまで 200 ms 待つ。`suspend()` は描画タスクを画面への通信の途中で凍結しうるので使わない。
- 家の Wi-Fi のパスワードは本体の NVS(`strider` 名前空間)にだけ保存する。設定用 Wi-Fi はパスワードなしで、設定が終わると出なくなる。
- 操作ページに認証は無い。同じ Wi-Fi につながっている人は誰でも操作できる。
- 「直接つなぐ」で本体が出す Wi-Fi にはパスワードが無い。電波の届く範囲の人は誰でもつないで操作できる。

## 試験用のファームウェア(旋回の試験)

`src/probe/yaw_probe.cpp` は、首を往復させてその場で旋回できるかを確かめるための試験用で、歩行用とは別の環境(`yawprobe`)でビルドする。歩けなくなるので、試験が済んだら歩行用を書き戻す。

```
pio run -e yawprobe
& $py -m esptool --chip esp32s3 --port COM8 --baud 921600 write-flash 0x20000 .pio\build\yawprobe\firmware.bin
```

- USB シリアル(115200)から 1 行ずつ指令を送る。指令の一覧は `yaw_probe.cpp` の先頭にある。
- 床で試すときは、指令を予約(`q`)してからケーブルを外し、画面をタッチする。動いている間のタッチで止まる。記録は本体に残るので、終わったらケーブルをつないで `d` で取り出す。
- **記録を、フラッシュ(16 MB)の最後の 128 KB(`0xfe0000` から)に書く。** 領域配置のどの領域にも入っていない所で、出荷時は空だった(2026-11-17 に読み出した個体)。歩行用のファームウェアは、ここに触れない。
- 予約した指令は NVS の `yawprobe` 名前空間に保存する。サーボの原点調整値(`servo`)には触れない。

2026-11-20 に実機で分かったこと:

- 連続回転(PWM)させている間も、首のサーボの位置は読める。1 回の読み取りに約 17 ms かかる。出力が正のとき、位置の値は減る。
- 位置が読めない区間が 1 周の約 1 割ある(生の位置 1022 と 3 の間)。そこでは 330〜415 前後などの、実際と違う値が返る。区間の端では 3 か 1022 が返る。
- 時計回り(上から見て)の旋回: `r 524 812 1000 <ミリ秒>`。両端を位置で折り返す。折り返しの指令から止まるまでに行き過ぎるので、実際の振れは 410〜927 くらいになる。
- 反時計回りの旋回: `v 260 80 1000 <ミリ秒>`。往復が読めない区間をまたぐ。区間に入る手前(位置 40 を下向きに通過)から 0.08 秒で折り返し、戻りは、区間を抜けたのを見てから上端で折り返す。上端 220〜260、遅れ 0.06〜0.10 秒で回った。
- 時間だけで折り返す `h` は、条件が少しずれると回らなくなった(読めない区間の値を、上端を越えたと取り違える)。区間の向こう側の位置で折り返す `w` は安定するが、折り返しが遅れて回る速さが落ちた。
- 首を回している間、パソコンとの USB 通信が切れることがあった(2 回)。原因は調べていない。回している間はシリアルに出さず、本体に記録する作りにしている。
- 位置の見積もりで折り返す往復(`e <中心> 144 1000 <ミリ秒>`)は、読めない区間が往復の端に来ても真ん中に来ても、規則正しく折り返した(折り返しの間隔 0.44〜0.52 秒)。中心 668 で時計回りに 5 秒 211°、中心 92(半周先)で反時計回りに 133°。歩行用のファームウェアは、この往復を使っている。
- 歩いている間の揺れ(出力 60%、`k 600 8000`): 前後の傾き(IMU の x 軸まわり)は 1 周に 2 回の成分が強く、山の位置は出力 40〜100% で 371〜431 に収まった。鉛直まわり(y 軸)は 1 周に 1 回の成分が強い(振幅 16〜56°/秒)が、山の位置は速さで 200 以上動いた。前者で位置を決め、後者で半周ずれた 2 つの候補から選ぶ。
- 揺れから求めた時計回りの中心は、往復の中心を 1 つずつ試して探した値 668 に対して、659・667・658・662・659・660(6 回)。2 つ目の歩行ベース(2026-11-21)では 329・328・326 で、その中心で時計回りに 5 秒 187°、反時計回りに 151° 回った。

## ビルド環境

- PlatformIO + pioarduino(Arduino-ESP32 3 系)。公式の StackChan-BSP が ESP-IDF 5 の API を使うため、PlatformIO 標準の環境(2 系)ではコンパイルできない。
- 依存: StackChan-BSP 1.1.1(コミット e2f3b02)、M5Unified 0.3.0、M5GFX 0.3.0、M5Stack-Avatar 0.10.0、IRremoteESP8266、M5Unit-NFC。
- `src/main.cpp`(動作)、`src/pages.h`(スマホに出す設定ページと操作ページ)。`src/probe/` は試験用で、歩行用のビルドには入らない。
